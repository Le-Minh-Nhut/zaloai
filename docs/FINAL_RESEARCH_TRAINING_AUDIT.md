## 1. Audit Method

All defects and findings reported across workstreams W1–W6 were subjected to empirical source code auditing and reproduction testing prior to acceptance:
- **Pre-Fix Reproduction**: Subagents inspected source code, constructed failing test cases reproducing each defect, and captured exact symptoms.
- **Root-Cause Analysis**: Defects were traced directly to file and line numbers, distinguishing causal logic errors (e.g. logit shift alignment, reference key leaks) from configuration or environment constraints.
- **Surgical Remediation**: Fixes were applied to the minimal set of files required, leaving peripheral logic untouched.
- **Dual-Runner Verification**: Every fix was verified using both the standard Python stdlib runner (`python3 tests/run_tests.py`) and pytest under `.venv` and `/tmp/torchenv` (PyTorch CPU).
- **Independent Verification**: Worker W6 independently inspected the repository source files at each cited `file:line` to verify that claimed fixes are physically present in the codebase.

## 3. Verified Correct (No Change Needed)

The following core components and invariants were audited and verified correct as designed:

1. **Causal Decision Point Invariant**: At decision step $k$, visible steps in prompt are strictly $0 \dots k-1$. Step $k$ observation is stored in `dp.observation_after` and never leaked into prompt. `assert_no_label_leak()` prevents any `label.final_state` leakage.
2. **Oracle ID Isolation**: Reference keys (`x-ref`, `x-match`, etc.) are tracked exclusively in `point.meta["unobservable_ref_args"]` and `point.meta["sample_flags"]`, never injected into agent decision prompts.
3. **Loss Masking Layout**: HF causal LM supervised training masks prompt tokens ($p_0 \dots p_{P-1}$) with $-100$ and supervision targets ($t_0 \dots t_{T-1}$) with label IDs. Gradient anti-leak test confirms zero gradient update from prompt tokens.
4. **Stopping Targets**: Zero-call samples emit a single terminal `<action>{"type": "finish"}</action>`. Samples ending with `sys.ask_missing_info` emit no `finish` point (asking user is terminal). Regular tool-calling sequences terminate with `finish`.
5. **Prompt Middle Truncation**: Target action is never truncated. When input length exceeds sequence budget, middle truncation cuts older dialog turns while preserving the head context (user request, installed apps) and schema tail.
6. **Train/Val Leakage Prevention**: Atomic group splitting hashes normalized transcript (diacritics stripped, casefolded, punctuation removed) + normalized history turns. `TrainVal.__post_init__` enforces zero group overlap between train and val splits.
7. **Chat Formatting Boundary**: Tokenizer chat templates strictly use `apply_chat_template(..., tokenize=False, add_generation_prompt=True)` with identical ChatML fallback across training and inference. Target has EOS token appended with no extraneous role markers.
8. **Trajectory Accounting**: Accounting statistics track and report `no_label`, `zero_calls_no_finish_possible`, `catalog_missing_tool`, and `empty_prompt`.
9. **Optimizer & Scheduler Plumbing**: Cosine learning rate scheduler with warmup, gradient clipping (`max_norm=1.0`), and AdamW parameter grouping function correctly in CPU venv.
10. **Agent Multi-Step Loop & State Tracking**: Tool execution cycles, observation feedback, loop termination, and state tracking conform to protocol across multi-step fixtures.

## 4. Risks Requiring Real Data / Real Weights / GPU / Official SDK

The following items cannot be validated within the local synthetic environment and remain operational risks until real resources are provisioned:

1. **Qwen3.5-4B VRAM & OOM Risk**: Full fine-tuning memory math estimates **69.98 GB** VRAM (fp32 master weights at 4 bytes/parameter, seq 8192, microbatch 1, gradient checkpointing on, `k = 2`). Must be verified on A100 (80GB) or H100 (80GB). Commodity GPUs must use LoRA (**11.31 GB** estimated at seq 8192 / microbatch 1, 0.73x of this machine's 15.45 GB free VRAM — 4.14 GB headroom). Both are estimator arithmetic from `memory_preflight`, not measured peak allocations.

   Two measured inputs behind those numbers. **Sequence budget** is now 8192 in every shipped config: at 4096 the collator middle-truncated 3299/4385 = 75.23 % of the SFT build and **27.7 % (921/3324)** of `tool_call` decision points lost the parameter-schema block of the tool they were asked to call (the literal `### <tool> (kind=` string in the decoded, truncated prompt, train+val `tool_call` targets), with the whole `# Công cụ khả dụng` section lost in **4.0 % (133/3324)**; at 8192 those fall to 1.05 %, 0.09 % (3/3324) and 0; since the 2026-11-08 collator change that pins the catalog to the preserved tail, schema-block loss is **0/3324** with truncation unchanged. **Precision**: full fine-tuning keeps fp32 master weights because AdamW writes its update into the parameter tensor — at `lr = 5e-6`, 20 steps moved only 7.4 % of bf16 elements versus 100 % of fp32 elements. bf16 speed comes from autocast.
2. **Official Simulator SDK Compliance (`zaic_tools`)**: The official `zaic_tools.ToolEnv` package is absent. While `OfficialToolEnv` strictly wraps its expected interface, runtime compatibility with the final organizer wheel can only be validated upon SDK release.
3. **Official Dataset Schema & Audio Properties**: Real competition audio duration, sample rates, noise levels, and non-standard JSONL metadata might differ from synthetic fixtures.
4. **ASR Model Quality on Real Vietnamese Speech**: Gipformer-68M-RNNT ONNX transducer performance (WER/CER, domain term accuracy) must be measured on real competition audio files. The metric path is now *wired* end to end (`scripts/transcribe_split.py` → `run_eda.py --asr-predictions` → `evaluate.py --asr-predictions`), but WER/CER remains **unmeasured** on real audio: no real weights and no labeled real split exist on this host, so every ASR number produced so far is synthetic-fixture or file-supplied only.
5. **Docker Container Execution**: Docker daemon was unavailable in the audit environment. The Dockerfile and entrypoint script are statically validated and linted, but live `docker run --network none` execution remains to be verified.
6. **Cloud Submission & W&B Remote Tracking**: Sandboxed runner was verified in `--dry-run` planning mode; live submission requires valid `WANDB_API_KEY` and remote compute quota.

## 5. Low-Priority Issues Intentionally Ignored

The following minor items were identified and documented but intentionally left unchanged to avoid destabilizing tested code:

1. **P2: Preflight Memory Overestimation for DeepSpeed ZeRO-3**: Memory preflight computes standard single-device AdamW memory footprints. If ZeRO-3 is configured in external wrappers, optimizer state is partitioned across devices, making the single-device estimate conservative. (Left as-is: conservative preflight prevents unexpected OOM).
2. **P2: Non-ASCII Character Logging in CLI Terminals**: Vietnamese diacritics in sample transcripts printed to stdout rely on terminal UTF-8 encoding. In legacy non-UTF8 environments, characters may be escaped. (Left as-is: standard modern Linux terminals default to UTF-8).
3. **P2: `W5-05` and `W5-06`**: Both were fixed during W5 and verified; no further P2 issues remain unresolved.
